# 今日の課題

AIを使って PC・スマホのアプリを作るとき、**どんな順番で、何をAIに任せればいいのか** を知る。

## 調査したこと

![AIアプリ開発フロー：7つの工程と主なAIツール](/images/learning/day007-app-dev-flow.png)

- アプリ開発の **7つの工程**（企画 → 設計 → デザイン → 実装 → テスト → リリース → 運用）
- 工程ごとに **人が決めること** と **AIに任せること**
- 工程ごとに使える **AIツール**（20種類ほど）
- 進め方の **コツと注意点**

くわしくは記事 [AIを活用したPC・スマホアプリ開発フロー](/articles/ai-app-dev-flow/) にまとめた。

## Discordで出た疑問

- AIがあれば、プログラミングを知らなくてもアプリは作れるの？
- ツールが多すぎて、どれから使えばいいの？
- スマホアプリを App Store に出すには何が必要？

## 実際に試したこと

:::tried[このサイトづくりと比べてみた]
このサイト自体が、資料の流れとほぼ同じ方法（要件を書く → CLAUDE.md にルール化 → Claude Code で実装 → 自動テスト → GitHub Actions で公開）で作られていることに気づいた。
:::

:::question
アプリそのものはまだ作っていない。小さなアプリを1つ作ってみる実験をしたい。
:::

## 分かったこと

- AIでのアプリ開発は、**7つの工程を小さくくり返す** のが基本。
- 人の役割は **「何を作るか」と「最終確認」**。作業の大半はAIに任せられる。
- 品質を決めるのは、実装よりも前に用意する **指示書**（要件定義書と [ルールファイル](/glossary/rules-file/)）。
- 実装の中心は [AIエージェント](/glossary/ai-agent/)（Claude Code、Cursor、Copilot、Codex、Antigravity など）。
- AIへの依頼は **1回1機能**。計画を確認してから実装させ、[Git](/glossary/git/) でこまめに保存する。
- スマホは **Webアプリ** と **ネイティブアプリ** で作り方がちがう。ストアに出すなら最初から決めておく。
- ストアへの登録や審査は、AIではなく **人がやる手続き**。

:::point[サイト更新時に追記した補足]
- **ストアの登録料**：Apple は年99ドル（毎年）、Google Play は25ドル（1回だけ）（Web記事で確認）。
- **AIが存在しない部品をすすめることがある**：実在しないパッケージ名を悪用する攻撃も報告されている。インストール前に確認する。
- **PWA**：ストアに出さずに、Webアプリをスマホのホーム画面に置いて使う方法もある。
- **APIキー**は `.env` に書いて Git に入れない。もれたらすぐ作り直す。
- 用語集に [MVP](/glossary/mvp/)、[要件定義書（PRD）](/glossary/prd/)、[クロスプラットフォーム](/glossary/cross-platform/)、[ノーコード](/glossary/no-code/)、[ルールファイル](/glossary/rules-file/)、[Git](/glossary/git/)、[プルリクエスト](/glossary/pull-request/)、[E2Eテスト](/glossary/e2e-test/)、[CI/CD](/glossary/ci-cd/)、[APIキー](/glossary/api-key/) を追加した。
- AIツール図鑑に Cursor、GitHub Copilot、OpenAI Codex、Google Antigravity を追加した。
:::

## 分からなかったこと

:::question
- 初心者は、ノーコードのアプリビルダーとコーディングエージェントのどちらから始めるのがよい？
- AIが書いたコードの著作権やライセンスはどうなる？
- 実際に作ると、どれくらいの時間とお金がかかる？
:::

## 今日の結論

AIがあれば、アプリ開発のハードルは大きく下がる。でも **「何を作るか決める」「指示書を書く」「最後に確かめる」** のは人の仕事。
まずは書類（要件とルール）を先に作って、小さく作って、こまめに保存するのが大事。
