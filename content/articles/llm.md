## 1. LLMとは

:::member[Day 8 のまとめより]
LLM は「Large Language Model（大規模言語モデル）」の略で、大量の文章を学習して、言葉を理解し、作り出せるようにしたAIのことです。ChatGPT、Gemini、Claude など、文章でやり取りする生成AIの中核になっています。
:::

| 言葉 | 意味 |
| --- | --- |
| Large（大規模） | 学習する文章の量も、モデル内部の数値（[パラメータ](/glossary/parameter/)）の数も、とても大きい |
| Language（言語） | 扱う対象が、人間の言葉であること |
| Model（モデル） | 学習を終えたAIの本体のこと（[モデル](/glossary/model/)） |

基本の動きは、**「この言葉の次に来やすい言葉は何か」を予測して、1つずつ言葉をつなげていく** ことです。これを大規模に学習させた結果、文章作成だけでなく、要約・翻訳・質問への回答・プログラムの作成までこなせるようになりました。

### 生成AI・ChatGPT との関係

```text
生成AI（文章・画像・音声・動画などを作るAI）
 └ LLM（そのうち「文章」を担当する部分）
     └ ChatGPT・Claude・Gemini などのサービス
        ＝ LLM ＋ 会話しやすい画面や機能
```

:::point[補足：サービスとモデルは別もの]
「ChatGPT」はサービス（アプリ）の名前で、その中で動いている LLM には別の名前（モデル名）があります。1つのサービスで、複数のモデルを選べることもよくあります（[モデル](/glossary/model/)）。
:::

:::warning
LLM は、意味を人間と同じように理解しているわけではなく、学習したパターンから「もっともらしい」答えを出しています。そのため、間違った内容を自信ありげに答えること（[ハルシネーション](/glossary/hallucination/)）があります。
:::

## 2. 文章を作るまでの流れ

| 順番 | すること | くわしく |
| --- | --- | --- |
| 1 | **トークンに分ける** | 文章を、単語や文字のかけら（[トークン](/glossary/token/)）に区切る。日本語だと1文字〜数文字ほどが1トークンになることが多い |
| 2 | **数値に変える** | 各トークンを、意味の近さを表す数値の並び（[エンベディング](/glossary/embedding/)）に変える |
| 3 | **文脈を読み取る** | [Transformer](/glossary/transformer/) の「[注意機構（アテンション）](/glossary/attention/)」が、どの言葉とどの言葉が関係しているかを計算する。たとえば「彼はそれを食べた」の「それ」が何を指すかを判断する |
| 4 | **次を予測する** | 次に来るトークンの候補を確率で出し、その中から1つ選ぶ |
| 5 | **くり返す** | 選んだトークンを文章に加えて、また次を予測する。これをくり返して長い文章になる |

:::point[補足：答えが少しずつ表示される理由]
ChatGPT などで、答えが1文字ずつ流れるように表示されるのは、この「1トークンずつ予測して足していく」しくみをそのまま見せているからです。
:::

:::point[補足：なぜ毎回ちがう答えになる？]
4 の「1つ選ぶ」ときに、いつも一番確率が高いものを選ぶのではなく、少しランダムに選んでいます。どれくらいランダムにするかの設定が [温度](/glossary/temperature/) です。
:::

:::point[補足：トークンだから苦手なこと]
LLM は文字そのものではなくトークンのかたまりで文章を見ています。そのため、「この単語に、ある文字がいくつ入っている？」のような **文字を数える問題** を間違えることがある、とよく話題になりました（最近のモデルではかなり改善されています）。
:::

## 3. 学習の段階

| 段階 | すること | ポイント |
| --- | --- | --- |
| [事前学習](/glossary/pre-training/) | 大量の文章を読ませ、「次の言葉の予測」をくり返して言葉の知識を身につけさせる | いちばん時間と費用がかかる |
| [追加の調整](/glossary/instruction-tuning/) | 質問と良い答えの例を学ばせ、指示に沿って答えられるようにする | チャットらしい受け答えになる |
| 人間のフィードバック | 人が回答を評価し、好ましい答え方に近づける（[RLHF](/glossary/rlhf/) など） | 安全性や話し方もここで整える |

:::member[Day 8 のまとめより]
事前学習だけでは、文章の続きを書くのは得意でも、質問に答えるのは上手ではありません。追加の調整があって、はじめてチャットで使いやすいAIになります。
:::

:::point[補足：たとえると]
- 事前学習 ＝ 図書館の本を片っぱしから読んで、言葉や知識を身につける
- 追加の調整 ＝ 「質問にはこう答える」という接客の練習をする
- 人間のフィードバック ＝ お客さんの評価を聞いて、答え方を直していく
:::

:::point[補足：最近の学習]
答える前にじっくり考える [推論モデル](/glossary/reasoning-model/) では、数学やプログラムのように **答えが正しいか自動で確かめられる問題** を大量に解かせて、考え方そのものを鍛える学習も行われていると言われています。
:::

## 4. 「大規模」の意味

| 大きいもの | 内容 |
| --- | --- |
| [パラメータ](/glossary/parameter/)数 | モデル内部の調整できる数値の数。数十億〜数兆規模のものもある |
| 学習データ量 | 本、Webの文章、プログラムのコードなど、ばく大な量を使う |
| 計算資源 | 大量のGPUを長い期間動かすため、学習にはとても費用がかかる |

一般に、規模を大きくすると能力が伸びる傾向があります（[スケーリング則](/glossary/scaling-laws/)）。ただし、小さくても工夫された軽量モデルも増えています。

:::point[補足：小さくするための工夫]
大きなモデルの知識を小さなモデルに受け継がせる [蒸留](/glossary/distillation/) や、モデルを軽くする [量子化](/glossary/quantization/) などの技術があります。
:::

## 5. モデルの種類によるちがい

| 種類 | 特徴 |
| --- | --- |
| 大きいモデル | 賢く、複雑な問題に強い。でも遅く、費用も高め |
| 小さいモデル | 速くて安く、手元のPCやスマホでも動かせる。かんたんな作業向き |
| [推論モデル](/glossary/reasoning-model/) | 答える前に時間をかけて考える。数学やプログラムなどの難問に強い |
| オープンなモデル | 公開されていて自分で動かせる（Llama など）→ [オープンソース](/glossary/open-source/)、[ローカルLLM](/glossary/local-llm/) |
| クローズドなモデル | 提供している会社のサービス経由でのみ使う（ChatGPT、Claude、Gemini など） |

:::point[補足：使い分けのヒント]
- ちょっとした質問・下書き → 速いモデル
- 調べものや長い文章の整理 → 大きいモデル
- 計算・プログラム・複雑な計画 → 推論モデル
- 入力した内容を外に出したくない → ローカルLLM（ただし性能の高いPCが必要）
:::

## 6. 限界と注意点

| 限界 | 内容 | 対策（補足） |
| --- | --- | --- |
| [ハルシネーション](/glossary/hallucination/) | 事実とちがう内容を自信ありげに答えることがある | 大事なことは出典で確認する |
| 知識の期限（[ナレッジカットオフ](/glossary/knowledge-cutoff/)） | 学習した時点までの情報が中心 | 検索機能つきのAIを使う |
| [コンテキストウィンドウ](/glossary/context-window/) | 一度に扱える文章量に上限があり、長い会話では前の内容を忘れることがある | 話題が変わったら新しいチャットにする |
| 計算が苦手なことがある | 計算ではなく「それらしい答え」を出すことがある | 計算ツールと組み合わせる（[ツール連携](/glossary/tool-use/)） |
| 中身が見えにくい（[ブラックボックス](/glossary/black-box/)） | なぜその答えになったのかを、人が完全には説明できない | 根拠や出典を一緒に出してもらう |

## 7. 今の広がり

| 発展の形 | 内容 |
| --- | --- |
| 検索との組み合わせ（[RAG](/glossary/rag/)） | 外部の資料を調べてから答えさせ、正確さを高める |
| [ツールとの連携](/glossary/tool-use/) | 計算、ファイル操作、Web検索などを自分で使う |
| [AIエージェント](/glossary/ai-agent/) | 目標に向けて、手順を考えながら作業を進める |
| [マルチモーダル](/glossary/multimodal/)化 | 画像・音声も扱う |

:::point[補足：つながっている話]
- ツールとの連携を共通のルールでできるようにしたのが [MCP](/glossary/mcp/) です。
- AIエージェントを使ったアプリ開発の流れは [Day 7](/learning/day007/) で学びました（[アプリ開発フロー](/articles/ai-app-dev-flow/)）。
:::
